7.3.Вкладка "Модификація меню-розкладки".

Ця вкладка містить функціонал для модифікаціі Excel файлів меню-розкладок які вдповідають видачі за тиждень. Це може бути корисно коли треба провести списання за меню-розкладкою, але кількість людей було змінено, тому розкладка на видачу не відповідає сітуаціі: потрібна нова меню-розкладка, яка буде "вірівнювати" кількість видатку по неї з реальним видатком по складу з точки зору кінцевих залишків за тиждень. Цей функціонал не змінює інформацію в поточній базі даних, тільки використовує інформацію про видаток та прибуток за тиждень для генераціі та збереження зміненої розкладки у вигляді Excel файла. Процес формування нової розкладки виглядає таким чином:

1) Спершу треба завантажити (імпортувати) рух товару за бажаний тиждень із зовнішнього Excel файлу або з поточного складу (кнопка 1). Цей рух можуть бути із зовнішньої программи, наприклад з ЗСУ Прод, чи можно використати рух за тиждень з цієї программи, це не має значення. Ідея полягає в тому, щоб можна було порівняти якийсь-то (зазвичай зовнішній) рух с потенційним рухом з меню-розкладки, та змінити меню-розкладку в випадку необхідності, щоб кінцевий залишок на тиждень був майже однаковий. Якщо зовнішній рух береться з програми ЗСУ прод, то можна сформувати звіт руху для кожного договору в ЗСУ прод за бажаний тиждень, експортувати в Excel, а потом об'єднати ці звіти за допомогою генератора "Об'єднання договорів ЗСУ прод" (див. вкладку "Звіти", тип звіту "Генератори"). Результат об'єднання в формі файла Excel ідеально підходить для завантаження зовнішнього руху во вкладку "Модификація меню-розкладки". Завантажений рух є початковою базою для формування нової меню-розкладки. Порівняння залишків на конець тижня проходить за схемою: зовнішній рух + рух по завантаженої меню-розкладці порівнюється з рухом по складу (або кільком складам), можлива коррекція відображається у відповідному стовпчику таблиці.
Далі треба завантажити в таблицю "Вибір файлів меню-розкладок" одну чи кілька розкладок, по яким буде рахуватися майбутній рух, видача або списання. Ці розкладки можно завантажити наприклад з програми ЗСУ Прод. Це можливо зробити у відповідної таблиці під назвою "Вибір меню-розкладок". Розкладок, по которим буде рух, та які можуть буде завантажені, може буди декілька (наприклад для різних підрозділів). Тому в таблицю "Вибір файлів меню-розкладок" треба завантажити усі бажані розкладки, але розкладка для модифікаціі повинна бути останьою у списку. Усі розкладки повинні містить відповідну кількість людей за кожен день.

2) На кроці 2 треба вказати період бажаного тижня та завантажити видаток та прибуток з поточного складу (кнопка 2). В разі необхідності до руху поточного складу може бути доданий рух по іншим складам. Для цього є відповідний функціонал по вибору відповідних баз даних. В випадку такого вибору, рух по всім складам у таблиці за обраний тиждень буде доданий до складського руху для порівняння. Після цих операцій таблиця порівняння буде показувати наступні дані:
- колонка імпортованих залишків
- колонка залишків на поточному складі (якщо було викристано завантаження залишків з поточного складу, дані в цієї колонці будуть однаковими з попередньою.)
- колонки "Надійшло", "Вибуло", "Залишок" - відповідно для поточного складу та зовнішнього руху (марковані як "імп." що означанє "імпорт"). Стовпчик "Вибуло по розкл." містить потенційний видаток, калькулюваний згідно завантаженим меню-розкладкам.
- Залишок по розкладці - ця колонка це розрахований сумарний залишок який буде якщо провести видаток (списання) згідно завантаженим в таблиці меню-розкладкам з урахуванням завантажених імпортованих залишків.
- "Різниця" - ця колонка містить різницю між залишком по розкладці та залишком на поточному складі.
- "Можлива коррекція" - дані у цієму стовпчику з'являються після натискання на кнопку 3, яка генерує нову, модифіковану розкладку, при цьому завантажені розкладки не змінюються, а базою для створення модифікованої розкладки є тільки остання розкладка із заватажених в таблиці. Ця модифікована розкладка на цьому етапі є тільки в оперативної пам'яті , і ніде не збережена. Зверніть увагу, що не всі коди підлягають автоматичної корекції. Кількість для кодів 4012, 2056 та 2057 можна змінити тількі вручну в збереженої нової розкадці, якщо це потрібно. Також автоматичная модифікація не виконується коли змінення дуже великі. В цьому випадку вважається що можлива якась помилка і це потребує ручного змінення людиною.
- "Коррекція для виконання" - в цієї колонці ви можете змінити коррекцію до бажаної, наприклад збільшити або зменшити. Здебільшего це використовується щоб не виконувати корекцію по якийсь позиціі - у цьому випадку потрібно виставити коррекцію в 0. Також зверніть увагу, що зі зовнішніх складів (якщо були вказані бази данних цих складів у відповідної таблиці) рух додається до руху поточного складу тільки в колонках початкових та кінцевих залишків. Це зроблено для того, щоб одразу бачити що прибуло та вибуло для поточного складу. Таке подання інформаціі може у деяких випадках бути нелогчіним, наприклад кінцевий залишок може бути менше початкового, при цьому в колонках надходження та видачі по поточному складу немає руху. Це явний показник того що рух відбувся в якийсь зовнішньої бази даних. Якщо вам потрібно бачити рух по звонішнім базам конкретної позиціі, виделіть цю позицію у таблиці та використайте контекстне меню (права кнопка миши).

3)На цьому кроці треба створити нову, модифіковану розкладку (кнопка "3 Генерувати розкладку"). Усі коригування відображаються у відповідних колонках таблиці. Якщо якась корекція небажана, її можно скоригувати у відповідній колонці "Коррекція для виконання". Зверніть увагу, якщо було завантажено кілька розкладок в таблицю "Вибір файлів меню-розкладок", то базою для модифікаціі та генераціі зміненої розладки будет тільки остання розкладка в таблиці. Також зверніть увагу, що алгорітм блокує коррекцію такої позиціі як вода (код 4012), яйця ( код по каталогу 2056, 2057), а також тих позицій, коррекція для яких є дуже велика. Це зроблено задля безпеки, тому що велика коррекція може означати якусь помилку в завантаженні даних. Наприклад, найбільш поширена помилка - початкові залишки були імпортовані не по всім договорам. Якщо цю коррекцію все ж таки потрібно зробити, це можливо безпосередньо в вже сгенерованому та збереженому файлі меню-розкладки.

4)Після генераціі нової меню-розкладки ви можете зберегти її у вигляді Excel файлу застосуванням відповідної кнопки 4("Зберегти нову розкладку"), збережена розкладка буде мати дані з урахуванням змін в колонці "Коррекція для виконання". Майте на увазі, що збережений файл нової розкладки може мати невірні макроси (з тієї причини що ісходний файл був закритий паролем). Щоб отримати повноціний файл меню-розкладки, створіть пустий файл меню-розкладки вашими штатними засобами (ЗСУ Прод та т.і.) та зробіть в ньому завантаження із збереженого файлу корегованої розкладки. Після цього цей файл можно використовувати в програмі ЗСУ Прод, для формування накладних, т.і.

Остання кнопка праворуч дозволяє зберегти залішки для роботи з наступним тижнем, якщо це необхідно. Зазвичай це використовується дуже рідко.
